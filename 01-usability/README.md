> **Учебная демонстрация.** Выполнено фактическое экспертное прохождение Moodle и подготовлена программа исследования. Результаты пяти условных участников ниже смоделированы; реальное тестирование с респондентами не проводилось.

## 1. Цель и объект

Цель — выяснить, насколько понятен студенту путь от поиска задания и материалов до подготовки результата к сдаче, и предложить улучшения.

Объект — модуль курса Moodle «Управление IT-проектами для корпоративного обучения»: разделы с заданиями, материалами SUS и форумом «Для загрузки результатов самостоятельной работы 2026-2027 уч.г».

Проверяемый сценарий: **найти требования → найти материал SUS → открыть форум → подготовить тему → вернуться в курс**. Основная роль — студент, уже имеющий доступ к курсу.

Границы: настольный браузер Chrome, русская версия интерфейса, доступная студенту область курса. Процесс входа не входит в измеряемые задания. Публикация, оценивание, мобильный интерфейс, работа внешней Google Формы и доступность для специальных средств не оценивались.

## 2. Программа исследования

Использован подход из предоставленных материалов: задания в привычном контексте, метод «думать вслух», фиксация времени, ошибок и незавершений. Сценарии интернет-магазина из примера заменены образовательными задачами. Размер демонстрационной группы — 5 условных участников.

### 2.1. Условные участники

Все профили вымышлены и соответствуют одной роли — студенту.

| Код | Профиль |
|---|---|
| P01 | Студент, впервые выполняющий работу в Moodle |
| P02 | Студент, использующий Moodle эпизодически |
| P03 | Студент, регулярно читающий материалы курса |
| P04 | Студент, имеющий опыт сдачи работ через форумы |
| P05 | Студент, помогающий одногруппникам пользоваться Moodle |

При реальном наборе следует обеспечить различный опыт Moodle и отсутствие участия в разработке курса. Пять сеансов подходят для небольшого качественного исследования, но не дают репрезентативной оценки всех студентов.

### 2.2. Задания и критерии завершения

Начальная точка T1–T3 — верх страницы курса после входа. Для T4 модератор предоставляет открытую страницу нужного форума, для T5 — ту же страницу форума. Такая установка исключает влияние провала предыдущего задания.

| Код | Инструкция участнику | Критерий успеха | Лимит |
|---|---|---|---:|
| T1 | «Найдите общие требования к оформлению результатов самостоятельной работы и скажите, где их сдавать». | Найдены общие указания курса; участник называет способ размещения ссылки и форум результатов. | 180 с |
| T2 | «Найдите пример анкеты SUS и ссылку, где объясняется эта шкала». | Найден ресурс SUS в теме 3 и ссылка MeasuringU. Переходы на внешние сервисы не требуются. | 180 с |
| T3 | «Найдите место для сдачи самостоятельной работы за 2026–2027 учебный год». | Открыт нужный форум в разделе «Результаты». | 180 с |
| T4 | «Подготовьте тему с названием и сообщением. Найдите, где можно прикрепить файл, и назовите ограничения. Остановитесь перед отправкой». | Заполнены учебные поля, открыта расширенная форма, найдены блок вложений, 500 Кбайт и 9 файлов. Сообщение не отправлено. | 240 с |
| T5 | «Вернитесь на страницу курса из форума». | Открыта страница курса по навигационной ссылке. | 60 с |

В T1 проверяются общие инструкции курса. Поиск полного текста трёх текущих задач отдельно в критерий успеха не включён: на проверенной странице ресурса этот текст отсутствует.

### 2.3. Проведение сеанса

1. Объяснить цель: исследуется интерфейс, а не способности человека. Получить согласие на запись наблюдений, использовать код участника.
2. Предложить выполнять действия привычным способом и вслух пояснять ожидания. Не показывать маршрут заранее.
3. Зачитать одно задание, включить таймер после окончания инструкции.
4. Зафиксировать время до критерия завершения или лимита, ошибочные переходы и необходимость помощи.
5. Если участник не продвигается 30 секунд и просит помощь, дать одну общую подсказку, не называя нужную кнопку. Пометить результат «с подсказкой».
6. При истечении лимита остановить попытку, восстановить начальную точку следующего задания. Для T4 отменить черновик после проверки.
7. После всех заданий предложить анкету SUS из второго отчёта. Не обсуждать удобство до её заполнения.

Вопросы после задания: «Что вы ожидали увидеть?», «Что было непонятно?», «Где вы искали нужную функцию?». При настоящем исследовании ответы записываются дословно с согласия участника. В демонстрации цитаты респондентов не создавались.

### 2.4. Метрики

| Метрика | Правило |
|---|---|
| Самостоятельное завершение | Число `success` / число всех попыток |
| Завершение с помощью | Число `assisted` / число всех попыток; отдельно от самостоятельного |
| Незавершение | Число `failed` / число всех попыток |
| Время попытки | Секунды от инструкции до успеха, помощи и успеха либо остановки |
| Ошибочные переходы | Число действий, не приближающих к цели; не включает ошибки сервера |
| Субъективное удобство | SUS после всех заданий; отдельный отчёт |

Число кликов и доля ошибок сервера не измерялись. Тайминги реального экспертного прохождения также не измерялись; они не смешиваются с модельной таблицей.

### 3.3. Реестр наблюдений

Приоритеты являются экспертным суждением: P1 — устранить первым, P2 — улучшить после критичных пояснений. Это не частота проблем у настоящих студентов.

| ID | Фактическое наблюдение | Возможное затруднение | Приоритет | Рекомендация |
|---|---|---|---|---|
| U01 | Страница задания содержит определение, без текста трёх задач; рис. 2. | Студент не может восстановить объём работы только по этому ресурсу. | P1 | Добавить три задачи, формат результатов, критерии приёмки и прямую ссылку на сдачу. |
| U02 | Форум для загрузки результатов предлагает «Добавить тему для обсуждения»; рис. 3. | Действие не очевидно связано со сдачей отчёта. | P1 | Перед кнопкой разместить инструкцию: «Чтобы сдать работу, создайте тему и укажите ссылку на отчёт». |
| U03 | Вложения доступны в расширенной форме; в быстрой отдельного блока нет; рис. 4–5. | Студенту с готовым файлом приходится обнаружить дополнительный переход. | P1 | Рядом с расширенной формой пояснить «Для прикрепления файлов» и заранее показать ограничения. |
| U04 | Пустой форум показывает отсутствие тем, но не пример названия и сообщения; рис. 3–4. | Неясно, какие сведения преподавателю нужны для идентификации работы. | P2 | Добавить закреплённый пример: номер задания, ФИО, группа, ссылка, состав приложений. |
| U05 | Материалы разных типов идут длинным списком с описаниями; рис. 1 и материал SUS во втором отчёте. | Нужный ресурс может потребовать прокрутки и чтения нескольких блоков. | P2 | Добавить компактное оглавление темы с якорями «Задание», «Программа», «SUS», «Сдать работу». |

Положительные свойства: понятные подписи полей, видимые отметки обязательности, текстовое пустое состояние, навигация обратно в курс, отдельная кнопка отмены. Проверка не выявляет и не доказывает нарушения доступности: отдельный аудит не проводился.

## 4. Модельные результаты

> Следующие таблицы — **вымышленные учебные данные**, а не протокол проведённых сеансов. Их назначение — показать обработку времени, ошибок и незавершений.

### 4.1. Исходная таблица

В ячейках: **секунды / ошибочные переходы / статус**.  
**С** — самостоятельно; **П** — с одной подсказкой; **Н** — не завершено до лимита.

| Участник | T1 | T2 | T3 | T4 | T5 |
|---|---|---|---|---|---|
| P01 | 170 / 2 / П | 180 / 3 / Н | 180 / 2 / Н | 240 / 1 / Н | 20 / 0 / С |
| P02 | 130 / 1 / П | 60 / 0 / С | 125 / 2 / П | 240 / 2 / Н | 18 / 0 / С |
| P03 | 75 / 0 / С | 45 / 0 / С | 85 / 1 / С | 165 / 1 / С | 16 / 0 / С |
| P04 | 55 / 0 / С | 35 / 0 / С | 65 / 0 / С | 130 / 0 / С | 15 / 0 / С |
| P05 | 60 / 0 / С | 40 / 0 / С | 70 / 0 / С | 140 / 1 / С | 17 / 0 / С |

### 4.2. Сводка

| Задание | Самостоятельно | С подсказкой | Не завершено | Среднее время попытки, с | Среднее самостоятельного успеха, с | Всего ошибочных переходов |
|---|---:|---:|---:|---:|---:|---:|
| T1 | 3/5 | 2/5 | 0/5 | 98 | 63,3333 | 3 |
| T2 | 4/5 | 0/5 | 1/5 | 72 | 45 | 3 |
| T3 | 3/5 | 1/5 | 1/5 | 105 | 73,3333 | 5 |
| T4 | 3/5 | 0/5 | 2/5 | 183 | 145 | 5 |
| T5 | 5/5 | 0/5 | 0/5 | 17,2 | 17,2 | 0 |

Сводка 25 модельных попыток:

- **18/25 = 72%** завершены самостоятельно.
- **3/25 = 12%** завершены с подсказкой.
- **4/25 = 16%** не завершены.
- **21/25 = 84%** завершены, если учитывать помощь.
- Всего **16** ошибочных переходов.

В демонстрационном наборе T4 даёт наибольшее среднее время попытки — 183 с — и два незавершения. T2 и T3 дают по одному незавершению. T5 все условные участники выполняют самостоятельно. Эти числа иллюстрируют возможный порядок внимания к задачам; они не подтверждают частоту проблем U01–U05 в реальном использовании.

Для незавершённых T2, T3 и T4 записан лимит. Поэтому среднее по всем попыткам нельзя трактовать как время, необходимое для успешного выполнения. Например, для T4 среднее самостоятельного успеха равно 145 с и рассчитано только по трём успешным попыткам.

### 4.3. Обработка

Исходные данные: [usability-model.json](../data/usability-model.json).  
Сводка: [usability-summary.json](../data/usability-summary.json).  
Скрипт: [summarize_usability.py](../scripts/summarize_usability.py).

```bash
python3 scripts/summarize_usability.py
```

Команда запускается из корня репозитория. Скрипт проверяет число попыток, уникальность пар «участник — задание», статусы, лимиты и неотрицательное число ошибок.

## 5. План улучшений и повторной проверки

| Порядок | Изменение | Как проверить после изменения |
|---|---|---|
| 1 | Обновить ресурс задания: три задачи и критерии отчётов | Новый участник объясняет состав результата, используя только страницу курса |
| 2 | Добавить в форум инструкцию и пример сдачи | Участник правильно выбирает создание темы и заполняет название и ссылку |
| 3 | Пояснить расширенную форму и ограничения вложений | Участник находит блок файлов без подсказки и называет ограничения |
| 4 | Сократить путь к заданиям и SUS через оглавление | Повторить T1–T3 и сравнить самостоятельное завершение и время |

Для следующего пилота можно принять внутреннюю цель: не менее 4 из 5 участников выполняют каждое задание без подсказки, критичные неверные трактовки способа сдачи отсутствуют. Это рабочий критерий проекта, а не норматив SUS. При настоящем сравнении следует использовать одинаковые задания, начальные точки и лимиты; по возможности привлечь новых людей, чтобы уменьшить эффект обучения.
